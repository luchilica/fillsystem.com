# CMS Integration Plan: Fill System

## Зачем этот документ

Поступил запрос: перевести сайт на WordPress, чтобы было легко редактировать шаблоны и контент. Этот документ объясняет, почему миграция на WordPress — регресс, какие альтернативы существуют, и даёт полный пошаговый план внедрения CMS-слоя поверх текущего сайта.

---

## Часть 1: Почему не WordPress

### Что уже построено

| Метрика | Значение |
|---------|----------|
| Маршруты (страницы) | 21 |
| Кастомные React-компоненты | 34 |
| CSS-модули (стилей) | 38 |
| Строк переводов (4 языка) | 2,066 |
| JSON-LD разметка (SEO) | в 16 файлах |
| Интерактивные компоненты | 6 (формы, cookie consent, аналитика, FAQ, калькулятор) |

### WordPress: что теряем

| Аспект | Текущий сайт (Next.js + Vercel) | WordPress |
|--------|-------------------------------|-----------|
| **Скорость** | ~50-100ms (edge CDN, static) | 800ms-2s без кеша |
| **Безопасность** | Zero attack surface (статика) | Цель #1 для атак (PHP, плагины, БД) |
| **Стоимость хостинга** | $0/год (Vercel free tier) | $200-500/год (хостинг + плагины) |
| **SEO-контроль** | Ручной JSON-LD, OG, alternates | Yoast/RankMath (ограниченнее) |
| **i18n (4 языка)** | next-intl, бесплатно | WPML €39/год, хуже |
| **Дизайн** | Кастомная система: fluid typography, duotone, PlusMark | Нужна кастомная тема (недели работы) |
| **Обслуживание** | Автоматическое (Vercel) | Постоянные обновления WP, PHP, плагинов |

### "Бесплатный WordPress" — миф

Реальная стоимость:
- Хостинг: $5-30/мес
- Премиум тема: $50-80
- WPML (переводы): €39/год
- Yoast SEO Pro: $99/год
- WP Rocket (кеширование): $59/год
- Плагин безопасности: $50-100/год
- Бэкапы: $50/год
- Форма обратной связи: $40-80/год
- **Итого: $350-550/год** vs **$0/год сейчас**

### "WordPress устаревает" — что за этим стоит

WordPress ещё держит ~43% рынка, но:
- Рост остановился (2022-2026)
- Скандал Matt Mullenweg vs WP Engine (2024) подорвал доверие экосистемы
- Gutenberg-редактор расколол сообщество
- Для новых проектов WordPress выбирают всё реже
- Тренд индустрии: headless CMS + современные фронтенды

### Headless WordPress — оверкилл

GPT предложил использовать WP как headless CMS. Проблема: для 21 страницы это как купить грузовик для поездки в магазин. Нужно поднимать и обслуживать WP-сервер только ради редактора, плюс GraphQL/REST-слой между WP и Next.js.

## Часть 2: Все альтернативы

### Профессиональные CMS-решения

| Решение | Тип | Стоимость | Сложность внедрения | Для кого |
|---------|-----|-----------|--------------------|----|
| **Keystatic** | File-based, Git | $0 | 1-2 дня | Один редактор, Git-версионирование |
| **Tina CMS** | File-based, Git | $0 (до 2 юзеров) | 2-3 дня | Визуальное WYSIWYG-редактирование |
| **Sanity** | Облачный headless | $0 (до 3 юзеров) | 3-5 дней | Несколько редакторов, коллаборация |
| **Builder.io** | Visual drag-and-drop | $0 (free tier) | 2-3 дня | Изменение структуры страниц |
| **Contentful** | Облачный headless | $0 (до 5 юзеров) | 3-5 дней | Корпоративный контент |

### Неофициальные / серые варианты

| Решение | Как работает | Стоимость | Плюсы | Минусы |
|---------|-------------|-----------|-------|--------|
| **Notion как CMS** | Контент в Notion, API забирает при сборке | $0 | Все уже умеют Notion | Нет визуального превью |
| **Google Sheets** | Таблица с данными → сайт пересобирается | $0 | Понятно любому | Только для табличных данных |
| **GitHub Web Editor** | Редактирование файлов прямо в браузере | $0 | Работает прямо сейчас | Нужно знать структуру файлов |
| **Claude Code** | ИИ редактирует по запросу на естественном языке | $20/мес (уже есть) | Уже используется | Нужен человек с доступом |
| **Airtable** | Структурированная БД как источник данных | $0 (free tier) | Гибкие схемы | API-лимиты |

### Рекомендация: Keystatic

Для Fill System оптимален **Keystatic**, потому что:

1. **Бесплатный и open-source** — без лицензионных расходов
2. **Контент в Git** — версионирование, откат, нет внешних зависимостей
3. **Коллекции** — идеально для услуг и статей (добавляй новые через админку)
4. **Синглтоны** — редактируемые блоки страниц (hero, FAQ, команда, статистика)
5. **Нативная интеграция с Next.js** — App Router, серверные компоненты
6. **Работает на Vercel free tier** — без дополнительной инфраструктуры
7. **Админка на `/keystatic`** — прямо на сайте, ничего отдельно ставить не нужно

### Фаза 0: Тест совместимости (1 день)

**Проблема:** Сайт на Next.js 16.2.9 (самая новая версия). Keystatic может не поддерживать её официально.

**Действия:**
1. Установить `@keystatic/core` + `@keystatic/next`
2. Создать минимальный конфиг `keystatic.config.ts` с одной тестовой коллекцией
3. Смонтировать админку на `app/keystatic/[[...params]]/page.tsx`
4. Смонтировать API-обработчик на `app/api/keystatic/[...params]/route.ts`
5. Добавить `keystatic` в исключения proxy.ts (чтобы i18n-маршрутизация не ломала админку)
6. Запустить `npm run dev` → открыть `/keystatic` → проверить что админка загружается
7. Запустить `npm run build` → проверить что продакшен-сборка проходит

**Если не работает (три запасных варианта):**
- **A:** Пропатчить адаптер `@keystatic/next` (он маленький, ~200 строк)
- **B:** Использовать Keystatic Cloud — админка хостится отдельно, не зависит от версии Next.js
- **C:** Подождать обновления Keystatic с поддержкой Next 16

### Фаза 1: Миграция блога (2-3 дня)

**Сейчас:** 12 статей, каждая — отдельный файл `page.tsx` с вшитым текстом на JSX. Метаданные в `components/blog/blogData.ts`.

**После:** Статьи хранятся как Markdoc-файлы в `content/posts/{slug}/index.mdoc`. Одна динамическая страница `[slug]/page.tsx` заменяет 12 статических.

**Что делается:**

1. **Схема коллекции `posts`** в Keystatic:
   - `title` — заголовок (slug генерируется автоматически)
   - `description` — краткое описание
   - `date` — дата публикации
   - `readTime` — время чтения ("7 min read")
   - `category` — категория (AI / RevOps / CRM / Strategy / Process / IT Security)
   - `heroImage` — обложка (загружается через админку)
   - `seoTitle` — SEO-заголовок (опционально)
   - `metaDescription` — мета-описание (опционально)
   - `authorName`, `authorTitle`, `authorLinkedin` — автор
   - `body` — текст статьи в формате Markdoc (визуальный редактор с заголовками, списками, ссылками, картинками)

2. **Миграция 12 существующих статей** из JSX в Markdoc:
   - `<h2>Title</h2>` → `## Title`
   - `<p>Text</p>` → просто текст с пустой строкой
   - `<Link href="/path">text</Link>` → `[text](/path)`
   - `<strong>bold</strong>` → `**bold**`
   - `<blockquote>` → `> quote`

3. **Замена 12 отдельных page.tsx** одним динамическим маршрутом `app/[locale]/blog/[slug]/page.tsx`, который читает контент из Keystatic

4. **Обновление `blogData.ts`** — из статического массива в асинхронную функцию `getBlogPosts()` через Keystatic reader

5. **Обновление карты сайта** (`sitemap.ts`) — динамический список статей из Keystatic

6. **Переводы:** Метаданные (заголовок, описание) продолжают переводиться через `t()`. Тело статьи отображается на английском для всех локалей (приемлемо — неанглийские локали noindex)

**Структура файлов после миграции:**
```
content/posts/
  revops-for-small-teams/index.mdoc
  hubspot-vs-salesforce-b2b/index.mdoc
  ai-agents-are-not-automation/index.mdoc
  ... (12 файлов)
```

**Как добавить новую статью (для редактора):**
1. Зайти на `/keystatic`
2. Нажать "Blog Posts" → "Create New"
3. Заполнить поля: заголовок, описание, категория, дата
4. Написать текст в визуальном редакторе (форматирование, картинки, ссылки)
5. Нажать "Save" → файл сохраняется в Git → сайт пересобирается автоматически

### Фаза 2: Миграция услуг (2-3 дня)

**Сейчас:** 9 услуг в массиве `SERVICES` в двух файлах. 7 детальных страниц услуг с уникальными массивами (шаги, FAQ, проблемы, что включено).

**Что делается:**

1. **Реестр иконок** (`lib/icon-registry.ts`):
   CMS не может хранить React-компоненты, поэтому создаётся маппинг: `"stethoscope" → <Stethoscope />`, `"zap" → <Zap />`, и т.д. В админке пользователь выбирает иконку из выпадающего списка.

2. **Коллекция `services`** — карточки на странице `/services`:
   - `title` — название услуги
   - `id` — технический идентификатор
   - `icon` — иконка (выбор из списка)
   - `description` — краткое описание
   - `price` — цена ("Free", "from $200", и т.д.)
   - `highlight` — выделить карточку
   - `href` — ссылка на детальную страницу
   - `image` — изображение для карточки на главной
   - `includes[]` — что входит
   - `sortOrder` — порядок сортировки

3. **7 синглтонов для детальных страниц** — по одному для каждой услуги:

   Каждый синглтон содержит поля, соответствующие структуре конкретной страницы:
   - **Advisory Power Hour:** steps[], topics[], deliverables[], FAQ[], цена, CTA
   - **Business Diagnostic:** reviewItems[], process steps[], FAQ[], сравнительная таблица, цена
   - **Add-on Tool Build:** buildOptions[], FAQ[], цена
   - **AI & Process Automation:** automationTypes[], process[], FAQ[]
   - **IT Risk & Security:** auditScope[], deliverables[], FAQ[]
   - **RevOps & CRM:** problems[], engagementScope[], FAQ[]
   - **Process & Operations:** problems[], deliverables[], FAQ[]

4. **Обновление страниц** — чтение данных из Keystatic вместо inline-массивов

5. **Сохранение JSON-LD** — та же логика генерации, только источник данных меняется с const-массивов на Keystatic

  o1-readiness-support.yaml

content/pages/
  advisory-power-hour.yaml    # контент детальной страницы
  business-diagnostic.yaml
  addon-tool-build.yaml
  ai-process-automation.yaml
  it-risk-security.yaml
  revops-crm-consulting.yaml
  process-operations.yaml

**Как добавить новую услугу (для редактора):**
1. Зайти на `/keystatic`
2. Нажать "Services" → "Create New"
3. Заполнить: название, описание, цена, иконка, ссылка

### Фаза 4: Проверка переводов (1 день)

**Принцип:** Keystatic управляет только английским контентом. Переводы остаются в `dictionary.ts` через систему `t()`.

**Как это работает:**
- CMS хранит тексты на английском
- Компоненты оборачивают значения из CMS в `t()`: `{t(service.title)}`
- `dictionary.ts` содержит переводы; для нового контента нужно добавить переводы вручную
- Тело статей блога отображается на английском для всех локалей

**Действия:**
1. Проверить, что все строки из CMS проходят через `t()` корректно
2. Убедиться, что ключи в `dictionary.ts` не сломались (английский текст должен совпадать точно)
3. Протестировать каждую локаль на корректность рендеринга
4. Задокументировать для редактора: "Если меняете английский текст в CMS — нужно обновить переводы в dictionary.ts"

**Путь развития переводов:**
Когда понадобится полноценная локализация контента, Keystatic поддерживает per-locale файлы: `content/posts/{slug}/en-US.mdoc`, `content/posts/{slug}/es-US.mdoc`. Это аддитивное изменение, не ломает текущий подход.

### Фаза 5: Продакшен-деплой (1 день)

**Режимы хранения Keystatic:**

| Режим | Где | Как работает |
|-------|-----|-------------|
| `local` | Разработка | Файлы читаются/пишутся на диск |
| `github` | Продакшен | Редактирование через админку → коммит в GitHub → Vercel пересобирает |

**Действия:**
1. Переключить Keystatic на `github` storage mode в продакшене
2. Создать GitHub OAuth App для аутентификации в админке
3. Установить env-переменные в Vercel: `KEYSTATIC_GITHUB_CLIENT_ID`, `KEYSTATIC_GITHUB_CLIENT_SECRET`
4. Задеплоить и проверить, что `/keystatic` работает в продакшене
5. Процесс: редактор открывает `/keystatic` → логинится через GitHub → редактирует → сохраняет → коммит в репозиторий → Vercel автоматически пересобирает сайт

**Важно:** Работает на Vercel free tier. Никакой дополнительной инфраструктуры не нужно.

### Фаза 6: Настройка домена (1 день, независимо)

Можно выполнить до, во время или после интеграции CMS.

1. **Купить домен** через любого регистратора
2. **Добавить домен в Vercel:** Project Settings → Domains → Add
3. **Настроить DNS** у регистратора (CNAME или A-запись → Vercel)
4. **SSL** — Vercel выпускает автоматически
5. **Установить env-переменные:**
   - `SITE_URL=https://yourdomain.com`
   - `SITE_MODE=production`
6. **Проверить после запуска:**
   - Canonical URLs используют новый домен
   - Sitemap на `/sitemap.xml` корректный
   - JSON-LD разметка содержит правильный домен
   - OG-теги (превью при шаринге) работают
   - Robots.txt не содержит noindex
7. **Подать sitemap** в Google Search Console
8. **Обновить OG share card** (сейчас placeholder без домена)
9. **Обновить footer** с реальным доменом
